## 🛠️ 실습 프로젝트 시작 가이드

1. 프로젝트 루트 경로에 안티그래비티의 규칙 파일인 `.antigravityrules`를 생성합니다. (내용은 [rules.md](file:///g:/%EB%82%B4%20%EB%93%9C%EB%9D%BC%EC%9D%B4%EB%B8%8C/%EC%99%80%EC%9D%B4%EC%95%A4%EC%95%84%EC%B2%98/%EC%99%80%EC%9D%B4%EC%95%A4%EC%95%84%EC%B2%98_%EA%B5%90%EC%9C%A1/260608_%EB%B0%94%EC%9D%B4%EB%B8%8C%EC%BD%94%EB%94%A9%20%EA%B5%90%EC%9C%A1/rules.md)를 참고하십시오.)
2. `index.html` 파일을 생성하고 기본 구조를 만든 후 개발을 시작합니다.
3. 안티그래비티 에이전트에게 구현하고 싶은 기능을 설명할 때, `rules.md`에 선언된 개발 표준을 준수하며 작성하도록 상기시킵니다.

## 📝 서비스 기획서 (실습용 템플릿)

*아래 프레임워크 항목을 바탕으로 자신만의 혁신적인 웹 서비스 기획을 완성해 보세요.*

### 1. 유저 (Target User)
* 서비스를 이용하게 될 대상은 누구이며, 어떤 페르소나 및 세그먼트적 특징을 가지고 있나요?
- **봉사자 개인**: 봉사하고 싶지만 정기 약속이 부담스러운 MZ세대 직장인·대학생. "생각날 때, 시간 날 때" 즉흥적으로 참여하고 싶은 니즈가 있음
- **봉사 기관**: 인력이 필요한 복지관·동물보호소·NGO 등. 노쇼와 당일 공백으로 운영에 어려움을 겪는 담당자
- **기업 CSR 담당자**: 임직원 봉사 실적을 관리해야 하는 중소기업 담당자

### 2. 문제점 (Pain Point)
* 타겟 유저가 평소 일상이나 업무에서 겪고 있는 핵심 불편 사항 및 요구 사항은 무엇인가요?
- 기존 1365 봉사포털은 사전 신청·정기 참여 중심으로, 즉흥적인 참여가 불가능함
- 봉사 의지는 있어도 신청 절차가 복잡하고 정기 약속이 부담되어 결국 참여를 포기하게 됨
- 기관 입장에서는 신청 후 노쇼율이 높고, 당일 갑작스러운 인력 공백이 빈번하게 발생함
- 봉사 후 이력 증빙 절차가 복잡해 참여 동기 자체가 떨어지는 구조

### 3. 해결 방안 (Solution)
- **매체**: 웹서비스 (순수 HTML/CSS/JS 바닐라 스택)
- **주요 기능 (1)**: 실시간 봉사 슬롯 매칭
  - *설명 및 UI 구상:* 기관이 "오늘 오후 2시, 2명 필요" 형태로 즉시 공고를 올리면 개인이 바로 신청. 메인 화면에 오늘/이번 주 열린 슬롯을 카드 형태로 나열하고, 위치·시간·분야 필터로 빠르게 탐색 가능
- **주요 기능 (2)**: 관심사 기반 추천 및 소셜 참여
  - *설명 및 UI 구상:* 아동·노인·환경·동물·장애인 등 카테고리 태그 설정 후 맞춤 기관 추천. 친구와 함께 신청하는 "같이 봉사" 버튼으로 동반 참여 유도. 참여 이력 기반으로 단골 기관 상단 노출
- **주요 기능 (3)**: 봉사 이력 자동 관리 및 인증서 발급
  - *설명 및 UI 구상:* 참여 완료 시 봉사 시간 자동 누적, PDF 확인서 즉시 다운로드. 기관·봉사자 상호 평가로 신뢰도 점수 형성. 마이페이지에 누적 시간·방문 기관·활동 분야를 시각화하여 표시

### 4. 기대효과 (Expected Effect)
* 서비스 도입을 통해 유저와 시장이 얻을 수 있는 정량적/정성적 가치는 무엇인가요?
- **봉사자**: 복잡한 절차 없이 원하는 시간에 바로 참여 → 봉사 경험자 수 증가 및 진입장벽 제거
- **기관**: 실시간 인력 수급 안정화, 노쇼 감소, 운영 효율 향상
- **사회적 가치**: 자발적 봉사 문화 확산 및 지역 복지 인프라 강화
- **기업**: CSR 활동의 실질적 연결 통로 마련, 임직원 참여 이력 관리 간소화
